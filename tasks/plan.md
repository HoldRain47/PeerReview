# 실행 계획: T002 평가 자료와 입력 처리 확보

- 기준: 개발 보고서 v2.0 8절 두 번째 단계, [목표정의서-v26100302.md](../docs/목표정의서-v26100302.md), [라벨지침-v26100302.md](../docs/라벨지침-v26100302.md)
- 작업 목록의 원본은 `.agents/state/STATE.json`의 `tasks`다. 이 문서는 설계 판단, 위험, 결정할 것을 담는다.
- 상태: 계획(사용자 검토 전). 아래 숫자와 출처 후보는 제안이며 조사·측정한 값이 아니다.

## 1. 이 단계가 끝나면 볼 수 있는 것

v2.0 8절의 통과 조건을 관측 가능한 결과로 바꿨다.

1. `data/`의 자료 목록을 열면 문서마다 출처, 이용 조건, 해시, 묶음(`bundle_id`), 라벨, 정답 근거 수준(A~D), 분리 위치(학습·검증·시험)가 있다.
2. 사람 작성(음성) 집단과 목표 행위(생성·재작성) 집단, 교정·번역 대조 집단이 모두 있다. 하나라도 없으면 T003으로 넘어가지 않는다.
3. 논문 파일 하나를 넣으면 페이지·문단 위치가 붙은 구간 목록과 처리 상태(`completed`·`partial`·`extraction_failed`·`too_short`·`out_of_scope`)가 나온다.
4. 추출 품질 기록에서 문서별 실패·제외 구간(수식, 표, 참고문헌, 그림 설명)을 확인할 수 있다.
5. 같은 묶음이 학습·검증·시험에 걸쳐 있지 않다는 것을 시험이 확인한다. 최종 시험 묶음 목록은 해시로 고정되어 있다.

## 2. 설계 판단

- **양성 자료는 사람 논문을 출발점으로 만든 짝 설계로 확보한다.** AI 보급 이전(D)의 사람 논문 한 편을 씨앗으로 삼아 특정 절을 AI로 생성·재작성·교정·번역한 변형본을 만들고, 원본과 변형본을 같은 묶음에 넣는다. 주제와 분야가 같은 상태에서 작성 방식만 달라지므로 비교가 공정하다. 바꾼 구간을 정확히 알고 있으므로 구간 정답(A 수준)도 함께 생긴다.
- **논문 전체 생성은 주 자료로 삼지 않는다.** 실제 투고에서는 일부 절만 AI를 쓰는 경우가 많다고 보고, 절 단위 치환(L06·L08·L15형)을 주로 만든다. 전체 생성본은 소수의 대조군으로만 둔다. 실제 사용 실태 통계는 확인하지 않았다(가정).
- **원문은 가능하면 PDF보다 구조화된 XML(JATS 등)을 쓴다.** Chemical Engineering 논문은 수식, 화학식, 아래첨자, 단위, 표, 반응식, 2단 편집이 많아서 PDF 추출 오류가 판정을 오염시킬 위험이 크다. 다만 실제 투고 원고는 PDF로 들어오므로, PDF 경로도 같은 문서로 시험해 XML 결과와 비교한다.
- **입력 처리는 원본을 바꾸지 않는다.** 원본 파일과 해시를 보존하고, 정규화한 분석용 사본에는 원문 위치 대응표를 둔다(v2.0 4절).
- **입력 처리 라이브러리는 직접 만들기 전에 기존 것을 비교한다.** 후보는 pypdf(BSD), pdfplumber(MIT), GROBID(Apache-2.0, 논문 구조 인식, Java 서버)다. PyMuPDF는 AGPL이라 배포 조건을 확인한 뒤에만 쓴다. 라이선스는 각 저장소에서 다시 확인한다(미확인).
- **자료 수집 시점에는 판정 코드를 만들지 않는다.** 신호 규칙과 문턱값은 T003의 일이다.

## 5. 라벨 일관성 확인이란

같은 자료를 두 번 따로 라벨해서 결과가 같은지 보는 확인이다. 라벨 지침 6절의 규칙(예: 자동 완성 L13, 크게 고친 AI 초안 L07)이 애매하면 같은 사람이라도 날마다 다르게 붙이거나 다른 사람과 판단이 갈린다. 그러면 정답 자체가 흔들려서 이후 측정한 오탐률과 재현율을 믿을 수 없다.

방법은 둘 중 하나다.
- 다른 사람 한 명이 지침만 읽고 같은 표본을 라벨한다.
- 혼자라면 1~2주 간격을 두고, 전에 붙인 라벨을 보지 않은 상태로 다시 라벨한다.

결과가 갈린 사례는 지침에 사례로 추가해 규칙을 분명하게 만든다. 짝 설계로 만든 변형본은 의도한 행위가 기록에 있으므로 대부분 쉽게 라벨할 수 있다. 이 확인이 실제로 쓸모 있는 곳은 경계 사례와 불확실 집단(C)이다.

## 6. 결정 (2026-10-03)

- **Q1 변형본 생성 모델:** 공개 논문에 한해 외부 API를 허용한다. AGENTS.md 4절에 예외를 넣었다(v26100301). 비공개 원고는 계속 외부로 보내지 않는다. 쓸 모델 계열과 비용 한도는 T002.5를 시작하기 전에 정한다.
- **Q2 자료 출처:** 공개 OA 논문과 사용자 보유 자료를 함께 쓴다.
- **Q3 최근 사람 작성 자료:** 작성 기록이 있는 자료는 없다. 사용자가 비공개 논문 1편을 가지고 있다. 쓰임새는 아래와 같다.
  - 로컬에서만 처리한다. 외부 API와 변형본 생성에 쓰지 않는다.
  - 실제 원고 형태의 PDF이므로 T002.2 입력 처리 시범의 대표 논문으로 쓴다.
  - 작성 기록이 없으므로 정답 근거는 C 수준이다. 불확실 집단으로만 분석하고 확정 음성 정답으로 쓰지 않는다. 1편이라 성능 수치에는 영향이 없고 사례 확인용이다.
  - 최근 사람 작성 자료가 사실상 없으므로, 시대에 따른 문체 차이의 위험은 한계로 기록한다.
- **Q4 규모:** 점검 2에서 확정한다(제안: 음성 시험용 300편 이상, 목표 행위 묶음 행위별 100개 이상).
- **Q5 라벨 일관성 확인:** 사용자가 혼자 1~2주 간격을 두고 30건을 다시 라벨한다.
