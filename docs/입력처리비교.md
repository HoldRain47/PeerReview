# 입력 처리 비교 (T002.2)

- 목적: 논문 PDF에서 본문을 뽑는 방법을 고른다. 판정은 본문 글자로 하므로, 글자를 잘못 뽑으면 판정 전체가 오염된다.
- 시험일: 2026-10-03. 대상은 공개 논문 5편(CC BY, 2020~2021)이다. 비공개 원고 결과는 7절에 사용자가 채운다.
- 재현: `uv run python scripts/compare_extraction.py data/public/pdf data/public/xml`

## 1. 방법

같은 논문의 출판사 XML(JATS)을 정답으로 삼았다. XML은 절·문단·수식·표·참고문헌이 태그로 나뉘어 있다. PDF에서 뽑은 본문을 XML 본문과 단어 단위로 맞춰 아래 지표를 쟀다.

| 지표 | 뜻 | 좋은 값 |
|---|---|---|
| recall | 정답 본문 단어 중 PDF 본문에서 찾은 비율 | 1에 가까울수록 |
| precision | PDF 본문 단어 중 정답 본문과 맞은 비율. 낮으면 표·그림 설명·수식·소속 정보가 섞였다는 뜻 | 1에 가까울수록 |
| order | 20단어 이상 연속으로 맞은 비율. 2단 편집에서 읽기 순서가 섞이면 낮아진다 | 1에 가까울수록 |
| chem | 정답의 화학식 토큰(CO2, Fe3O4 등) 중 PDF에서 그대로 찾은 비율 | 1에 가까울수록 |
| ref_leak | 참고문헌이 본문으로 섞여 든 비율 | 0에 가까울수록 |

## 4. 결정과 근거

**pypdf를 채택한다.** 5편 모두 모든 지표에서 pdfplumber보다 같거나 낫고, 2~3.5배 빠르다. 라이선스는 BSD-3-Clause이고 순수 Python이다. Windows 설치와 시험 통과는 이 변경을 push한 뒤 CI(windows-latest)에서 확인하며, 최종 확인은 사용자의 Windows 10 환경에서 한다. pdfplumber는 비교용으로만 남긴다.

시험 중에 고친 문제(첫 측정 → 최종):

| 문제 | 조치 | 효과(pypdf) |
|---|---|---|
| 참고문헌 제목이 문단에 섞여 참고문헌이 본문으로 들어감 | 참고문헌 제목을 줄 단위로 찾는다 | ref_leak 0.10~0.80 → 0.00~0.003 |
| 합자(ﬁ 등)로 단어가 쪼개짐 | 분석용 사본을 NFKC로 정규화(원본은 그대로) | 합자 68~123곳 → 0 |
| RSC 전용 글꼴이 fi·빼기·등호를 엉뚱한 문자로 냄 | 알려진 깨짐 문자표로 복구하고 횟수를 기록 | PMC8978821에서 299곳 복구 |
| 쪽마다 띄어쓰기가 다른 바닥글이 남음 | 숫자·공백을 무시하고 쪽 가장자리 두 줄만 비교 | RSC 바닥글 제거 |
| 그림·표 설명이 본문에 섞임 | "Fig. 1 대문자…" 형태를 설명으로 분리. "Fig. 2 shows…"는 본문으로 둔다 | RSC precision 0.58~0.64 → 0.86~0.91 |
| 심사용 원고의 줄 번호(예상 문제) | 쪽의 절반 이상이 숫자로 시작하면 줄 번호로 보고 지운다 | 가상 원고 시험 통과. 공개 5편 지표 변화 없음(오작동 없음) |

## 5. 위치 대응과 검증 후 보완

- **위치 대응:** 구간마다 원문 위치(`loc`)를 남긴다. PDF는 `p3:L12-18`처럼 추출기가 낸 정규화 전 글자의 쪽·줄 범위이고 `source_text()`로 원래 줄을 되찾는다. 글꼴 복구·합자 풀기·줄 번호 지우기를 해도 줄 수는 바꾸지 않아 대응이 유지된다. XML은 `body[1]/sec[2]/p[3]` 같은 요소 경로이고 `resolve_jats()`로 되찾는다. 공개 5편의 PDF 구간 861개와 XML 구간 776개가 모두 되돌아갔다.
- **검증 역할(verifier) 지적을 반영함:**
  - 한국어 본문에 영어 참고문헌이 섞이면 영어로 판정되던 오류를 고쳤다(라틴 문자가 아닌 낱말 비율로 판별). "참고문헌" 제목도 인식한다.
  - `--out`이 입력 파일과 같으면 실행을 거부해 원본 덮어쓰기를 막는다.
  - 줄 번호는 쪽의 70% 이상이 숫자로 시작하고 그 숫자가 1씩 늘 때만 지운다(번호 매긴 참고문헌·숫자 표 오작동 방지).
  - 쪽 번호는 "쪽 순서 + 상수"를 3쪽 이상 따를 때만 지워, 가장자리의 숫자 표 행을 남긴다.
  - XML의 문단 안 그림 설명과 절 바로 아래 목록·인용을 빠뜨리지 않는다.
  - XML이 깨졌거나 PDF 한 쪽만 실패하면 프로그램이 멈추지 않고 각각 `extraction_failed`, `partial`로 기록한다.
  - 수식 자리표시자를 단어 수에서 뺀다.

사용자가 원고에서 확인한 문제와 조치다. 원고 원문은 기록하지 않는다.

| 문제 | 조치 | 공개 5편 영향 |
|---|---|---|
| 그래프 안의 축 눈금·범례 글자가 본문 문단으로 뽑힘 | 6토큰 이상이고, 문장 부호로 끝나지 않으며, 숫자 토큰이 30% 이상이고 영어 기능어가 10% 미만인 구간을 `figure_text`로 분리. "(a)" 같은 패널 표시는 관사로 세지 않음 | recall 변화 없음, precision 소폭 상승(표 내용 일부도 분리됨) |

| 대문자 표 제목(TABLE 1) | 표·그림 제목 규칙에 대문자형과 로마 숫자 추가 | 변화 없음 |

새 명령 `peerreview inspect <파일>`은 원문 없이 품질 지표만 낸다(7절).

### 비공개 원고 2차 실행 후 보완 (2026-10-04)

2차 `inspect`에서 문단 중앙값 52단어, 문장 부호 없이 끝나는 본문 23개, 숫자로 시작하는 본문 22개, 본문 안 깨진 글자 18개가 나왔다. 절 제목과 수식이 본문에 섞인 것으로 보고 다음을 추가했다.

| 문제 | 조치 | 공개 5편 영향 |
|---|---|---|
| 절 제목("2.1 Materials")이 본문 문단에 붙음 | 번호 붙은 12단어 이하 제목, 이름 있는 절 제목(Introduction 등)을 `heading`으로 분리. 다음 줄이 소문자로 이어지면 번호 목록 항목으로 보고 제목으로 보지 않음 | 첫 규칙은 결론의 번호 목록 첫 줄을 제목으로 떼어 냈다. 조건을 더해 해결 |
| 감사의 글·저자 기여·연구비·이해 상충·기호표(Nomenclature)·윤리 진술이 본문에 섞임 | 표지가 나온 뒤 참고문헌 전까지의 본문을 `back_matter`로 분리. XML도 같은 절을 `back_matter`로 둔다 | 정답 XML이 이 절들을 본문으로 담고 있어 처음에는 recall이 떨어진 것처럼 보였다. XML에도 같은 분류를 적용해 기준을 맞췄다 |
| 첫 쪽의 학술지명·제목·저자·소속이 본문에 섞임 | 초록이나 서론이 처음 3쪽 안에서 시작하면, 그 앞의 문장 아닌 조각을 `front_matter`로 분리. 60단어 이상인 문장 구간(표지 없는 초록)은 본문에 남김 | 처음에는 RSC의 표지 없는 초록까지 빠져 recall이 0.911→0.878로 떨어졌다. 조건을 더해 복구 |
| 수식이 왜 분리되지 않는지 알 수 없음 | `inspect`에 등호와 "(번호)"가 있는 본문 문단 수, 그중 깨진 글자가 있는 수, 낱말이 섞여 떼어 내지 못한 수를 추가 | — |

검증 역할이 본문을 잃는 경우 3건을 지적했다. "Funding agencies increasingly require …" 같은 본문 문장을 뒷부분 표지로, "Introduction of a catalyst …"를 서론 표지로, "3 Results were obtained at 25 °C"와 표 행 "2 Ethanol 78 79"를 제목으로 보는 경우다. 그래서 표지는 제목 줄이나 "표지:" 형태만 인정하고, 뒷부분이 아닌 제목이 나오면 본문으로 돌아가게 했다. 번호 제목에는 동사 없음, 관사·전치사로 끝나지 않음, 숫자 토큰 2개 미만 조건을 더했다. 동사가 있는 12단어 이상 문장은 앞부분으로 보내지 않는다. 지적된 예문은 모두 시험에 넣었다.

최종 결과(pypdf): recall 0.848~0.993(보완 전 0.850~0.995), precision은 MDPI 3편에서 0.497~0.692 → 0.545~0.713으로 올랐다.

## 6. 남은 한계

- **1단 MDPI 논문의 precision이 0.55~0.71이다.** 앞부분·뒷부분은 분리했지만 표 안의 셀 글자와 일부 그래프 글자가 본문에 남는다.
- **2단 RSC 논문의 order가 0.71~0.81이다.** 단 사이에 그림·표가 끼면 읽기 순서가 섞인다.
- **화학식이 쪼개진다(chem 0.53~0.80).** PDF에서 아래첨자가 띄어쓰기로 떨어져("H 2O") 같은 토큰으로 맞지 않는다. 화학식 자체는 판정 신호가 아니므로 당장은 기록만 한다.
- **번호 없는 수식은 PDF에서 구분하지 못한다.** 번호 붙은 수식 줄만 떼어 내고, 아래첨자 낱말이 든 수식("JH2O = … permeate …")은 보수 규칙 때문에 본문에 남는다.
- **수식 줄과 뒤 설명을 나눈 두 구간은 같은 원문 줄을 가리킨다.** 위치 대응은 줄 단위라 글자 단위로 정확하지는 않다.
- **표·그림 제목 바로 다음 줄이 빈 줄 없이 본문이면, 그 줄도 제목 구간에 붙는다.**
- **글꼴 복구표는 RSC 2편에서 확인한 글자만 담았다.** 다른 출판사의 깨짐은 새로 확인해야 한다. 깨짐 흔적이 있는 문서에서는 진짜 ¼도 "="로 바뀐다.
- **결론: 공개 논문은 XML을 주 입력으로 쓰고, PDF는 실제 투고 원고 처리용이다.** 실제 투고 원고는 저자가 Word 등으로 만든 PDF라 출판사 PDF와 성질이 다르다. 그래서 비공개 원고 결과(7절)가 중요하다.

## 7. 비공개 원고 결과 (사용자 실행)

에이전트는 이 원고를 읽지 않는다. 원문이 담긴 파일, 화면 캡처, 복사한 글은 대화에 보내지 않는다. 보내면 모델 제공자 서버로 전송된다.

사용자가 별도 터미널에서 아래 두 명령을 실행하고, **화면 출력(숫자만)** 을 대화에 붙여 넣는다.

```
uv run peerreview ingest data/private/manuscript-001.pdf
uv run peerreview inspect data/private/manuscript-001.pdf
```

`inspect` 읽는 법:

| 항목 | 뜻 | 의심할 상황 |
|---|---|---|
| body_paragraph_words, _median | 본문 문단 길이 분포 | `<10`·`10-29`가 많거나 중앙값이 40 미만이면 문단이 쪼개졌거나 조각이 섞였다 |
| body_not_ending_with_punctuation | 문장 부호로 끝나지 않는 본문 문단 수 | 많으면 문장 중간에서 끊겼다 |
| body_starting_lowercase | 소문자로 시작하는 본문 문단 수 | 많으면 앞 문단에서 잘못 끊겼다 |
| body_starting_with_digit, body_mostly_numbers | 숫자로 시작하거나 숫자가 많은 본문 문단 수 | 많으면 줄 번호·그림 글자·표가 섞였다 |
| broken_glyphs_in_body | 본문에 남은 깨진 글자 수 | 0이 아니면 수식·기호 글꼴 문제 |
| body_equation_like (_with_broken_glyphs, _with_words) | 등호와 "(번호)"가 있는데 본문에 남은 문단 수(그중 깨진 글자가 있는 수, 낱말이 섞여 수식으로 떼지 못한 수) | 많으면 수식이 문장과 붙어 있다 |
| pages_without_body | 본문이 하나도 없는 쪽 | 그림·표만 있는 쪽이면 정상, 아니면 추출 실패를 의심한다 |
