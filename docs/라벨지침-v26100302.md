# 라벨 지침 v26100302

- 작업: T001 (개발 보고서 v2.0 8절 첫 단계)
- 적용 범위: [목표정의서-v26100302.md](목표정의서-v26100302.md) 2절(영어, Chemical Engineering, 연구 논문)
- 목적: 같은 자료를 누가 라벨해도 같은 관여 행위와 목표 행위 여부를 고르게 한다. 정답은 작성 과정 기록으로 정하며, 문체 인상이나 다른 탐지기의 출력으로 정하지 않는다(v2.0 5절).
- 상태: 초안. 6절 경계 사례는 제안 규칙이며 실제 자료로 라벨 일치도를 확인하지 않았다.

## 1. 라벨 단위와 필드

판정 단위는 논문 한 편이다. 구간 라벨은 작성 기록으로 위치를 확인할 수 있을 때만 붙인다.

| 필드 | 값 | 설명 |
|---|---|---|
| `doc_id` | 문자열 | 문서 식별자 |
| `bundle_id` | 문자열 | 같은 저자, 같은 원논문과 그 변형본, 같은 생성 입력에서 나온 자료를 묶는 식별자. 학습·검증·시험 분리의 단위다 |
| `target_present` | 예 / 아니오 / 미상 | 논문 어느 구간에든 1차 목표 행위(`TARGET_ACTS`)가 있었는가 |
| `acts` | `InvolvementAct` 값 목록 | 확인된 관여 행위 전부. 없으면 빈 목록, 모르면 `unknown` |
| `spans` | 구간 목록 | 행위별 영향 구간(절·문단 위치). 기록으로 확인하지 못하면 비운다 |
| `truth_basis` | A / B / C / D (2절) | 정답 근거의 수준 |
| `checked_scope` | 문자열 | 기록이 확인해 주는 범위(예: "Introduction과 Discussion의 생성 기록만 있음") |
| `tools` | 문자열 목록 | 사용한 도구·모델·버전·시점. 모르면 비운다 |
| `notes` | 문자열 | 경계 판단의 이유. 6절 사례 번호를 적는다 |

미확인 정보는 빈 값으로 남긴다. 추정으로 채우지 않는다.

## 2. 정답 근거 수준

| 수준 | 조건 | 성능 평가에서의 쓰임 |
|---|---|---|
| A | 통제된 작성 과정의 기록(원출력, 변경 이력, 생성 입력)이 있고 진위와 원고 연결을 확인했다 | 확정 정답 |
| B | 기록이 있으나 일부 구간·시점만 확인된다 | 확인된 행위에 대해서만 확정 정답. `target_present = 아니오`의 근거로는 쓰지 않는다 |
| C | 작성자 진술이나 버전 이력 하나뿐이다 | 불확실 집단으로 따로 분석 |
| D | AI 도구 보급 이전에 공개된 자료(사람 작성 기준 자료) | 음성(사람 작성) 확정 정답. 현재 문체와의 시대 차이 때문에 현재의 사람 작성 자료(A)와 함께 쓴다 |

D의 기준일은 T002에서 정한다. 대화형 생성 모델이 널리 쓰이기 전 시점을 쓰되, 그 이전에도 생성 모델이 있었다는 한계를 자료 목록에 적는다.

## 3. 행위 정의

입력·출력과 편집 과정을 대조해 정한다. 도구의 기능 이름(예: "Rewrite", "Polish")만으로 정하지 않는다(v2.0 2절).

- 본문 생성 `generation`: AI가 원고에 들어갈 문장이나 문단을 새로 산출했다. 사람이 준 개요·메모·키워드를 문장으로 풀어 쓴 경우도 포함한다.
- 재작성 `rewriting`: 사람이 쓴 원문을 바탕으로 AI가 문장 구조나 표현을 실질적으로 다시 구성했다. 문장 합치기·나누기, 절 순서 바꾸기, 같은 내용을 다른 표현으로 다시 쓰기가 여기에 든다.
- 교정 `proofreading`: 철자·문법·구두점·관사·수 일치처럼 오류를 제한적으로 고쳤다. 문장 구조와 논리 연결은 그대로다.
- 번역 `translation`: 다른 언어로 쓴 사람의 원문을 AI가 영어로 옮겼다. 내용의 작성자는 원문 작성자다.
- 혼합 작성 `mixed`: 한 구간 안에 사람이 쓴 부분과 AI가 생성한 부분이 섞였다.
- AI 초안을 사람이 수정 `human_edited_ai`: AI 초안이 출발점이고 사람이 고쳤다. 수정 정도와 관계없이 이 값이다.
- 검색·아이디어 정리 `search_ideation`: 문헌 검색, 개념 설명, 구성 상의를 했지만 원고 문장은 사람이 썼다.
- AI 출력 인용 `quoted_ai_output`: 연구 대상이나 예시로 AI 출력을 원고에 인용하고 인용임을 밝혔다.
- 미상 `unknown`: 기록으로 행위를 정할 수 없다. 편의상 사람 작성이나 생성으로 배정하지 않는다.

## 4. 판정 절차

1. 자료가 지원 범위 안인지 본다. 밖이면 라벨하지 않고 범위 밖으로 기록한다.
2. 정답 근거 수준(A~D)을 먼저 정한다.
3. 기록이 보여 주는 행위를 구간별로 `acts`와 `spans`에 적는다. 한 논문에 여러 행위가 있으면 모두 적는다.
4. `acts`에 `TARGET_ACTS`가 하나라도 있으면 `target_present = 예`다.
5. 목표 행위가 없다는 근거가 A 또는 D이면 `아니오`, 그 밖에는 `미상`이다.
6. 6절 사례와 비교해 경계 판단의 이유를 `notes`에 적는다. 맞는 사례가 없으면 새 사례로 제안하고 사용자 결정을 받는다.

임시 규칙: 생성형이 아닌 신경망 기계 번역 도구도 `translation`으로 적고 `tools`에 도구명을 남긴다. T002에서 확정한다.

## 5. 교정과 재작성의 경계 검사

다음 중 하나라도 해당하면 교정이 아니라 재작성이다.

- 문장을 합치거나 나눴다.
- 주절과 종속절, 능동과 수동처럼 문장 구조를 바꿨다.
- 연결어나 논리 표지를 새로 넣거나 바꿔 문장 사이의 관계를 바꿨다.
- 오류가 아닌 내용어(명사·동사·형용사)를 다른 표현으로 바꿨다.
- 원문에 없는 수식어·평가어·요약 문장을 넣었다.

모두 해당하지 않고 고친 부분이 오류 수정뿐이면 교정이다. 편집 거리 같은 수치는 참고만 하고 판정 기준으로 쓰지 않는다. 수치 문턱은 일치도 시험 없이 정하지 않는다.

## 6. 경계 사례와 반례

예시 문장은 설명용 가상 문장이다. 실제 논문이나 저자에서 가져오지 않았다.

| 번호 | 상황 | 라벨 | `target_present` | 이유 |
|---|---|---|---|---|
| L01 | 사람이 쓴 "The results shows that the model perform well" 을 AI가 "The results show that the model performs well" 로 고쳤다 | `proofreading` | 아니오 | 수 일치 오류만 고쳤다 |
| L02 | 도구의 "Rewrite" 기능을 썼지만 결과물이 L01처럼 문법 오류만 고쳤다 | `proofreading` | 아니오 | 기능 이름이 아니라 입출력으로 정한다(반례) |
| L03 | 사람이 쓴 두 문장 "We used X. It was fast." 를 AI가 "Leveraging X, we achieved notable efficiency gains." 로 바꿨다 | `rewriting` | 예 | 문장을 합치고 평가어를 넣었다(5절) |
| L04 | 사람이 한국어로 쓴 초안 전체를 AI로 영어 번역했다 | `translation` | 아니오 | 내용 작성자는 사람이다. 목표 행위로 표시하면 오탐이다 |
| L05 | L04 번역문을 다시 AI에 "make it more academic" 으로 넣어 문장 구조가 바뀌었다 | `translation`, `rewriting` | 예 | 번역 뒤 재작성이 따로 일어났다. 구간을 나눠 적는다 |
| L06 | 사람이 bullet 개요를 주고 AI가 Related Work 문단으로 풀어 썼다 | `generation` | 예 | 아이디어가 사람 것이어도 문장은 AI가 산출했다 |
| L07 | AI가 Introduction 초안을 쓰고 사람이 대부분 다시 썼다 | `human_edited_ai` | 예 | 출발점이 AI 초안이다. 사람 수정 정도와 관계없다. 결과는 따로 보고한다 |
| L08 | 한 문단 안에 사람이 쓴 문장 3개와 AI가 생성한 문장 2개가 섞였다 | `mixed` | 예 | 구간 기록이 있으면 문장 단위로 `spans`를 적는다 |
| L09 | AI로 관련 문헌을 검색하고 개념 설명을 들은 뒤 사람이 직접 썼다 | `search_ideation` | 아니오 | 원고 문장을 AI가 산출하지 않았다 |
| L10 | 공정 설계에 LLM을 시험한 논문이 ChatGPT의 공정 조건 제안 응답을 결과로 인용 블록에 실었다 | `quoted_ai_output` | 아니오(인용 구간) | 연구 자료의 인용이다. 나머지 본문은 따로 판단한다 |
| L11 | 사람이 쓴 글에 "delve", "Furthermore", "In this paper, we" 가 많다 | `acts` 없음 | 아니오(A·D 근거일 때) | 상투 표현은 사람도 쓴다. 문체 인상은 정답 근거가 아니다(반례) |
| L12 | 사람 전문 교열자가 문장을 대폭 다듬었다 | `acts` 없음 | 아니오(A 근거일 때) | 사람의 재작성은 AI 관여가 아니다. 문체 신호의 오탐 점검용 반례다 |
| L13 | 편집기 자동 완성으로 문장 끝 단어 몇 개를 받아들였다 | `proofreading` | 아니오 | 단어 수준의 보완이다. 한 문장 이상을 받아들였으면 L06처럼 `generation`이다 |
| L14 | 다른 논문 문장을 표절 회피 목적으로 AI에 바꿔 쓰게 했다 | `rewriting` | 예 | 원문을 바탕으로 표현을 다시 구성했다. 표절 여부는 이 지침의 판단 대상이 아니다 |
| L15 | 초록(Abstract)만 AI가 생성했고 본문은 사람이 썼다 | `generation` | 예 | 문서 단위 판정은 어느 구간에든 목표 행위가 있으면 예다. 영향 구간은 초록으로 한정한다 |
| L16 | 저자가 "AI는 교정에만 썼다"고 진술했지만 기록이 없다 | `unknown` | 미상 | 근거 수준 C. 불확실 집단으로 분석한다 |
| L17 | 생성 기록이 있지만 해당 원고와 어느 판본에서 연결되는지 확인하지 못했다 | `unknown` | 미상 | 진위·연결 미확인 자료는 확정 정답으로 올리지 않는다(v2.0 3절) |
| L18 | 원고에 `utm_source=chatgpt.com` 링크가 있지만 작성 기록은 없다 | `unknown` | 미상 | 링크 경유의 단서일 뿐 본문 작성 관여의 근거가 아니다(v2.0 7절) |

## 7. 지침 관리

- 라벨러 사이에 판단이 갈린 사례는 6절에 새 번호로 추가하고 결정 이유를 적는다.
- 라벨 기준이 바뀌면 영향을 받는 자료와 평가 결과를 기록하고, 이미 최종 시험에 쓴 자료라면 그 시험을 독립 시험으로 보지 않는다(v2.0 5절).
- 개정하면 파일명 버전을 올린다.
